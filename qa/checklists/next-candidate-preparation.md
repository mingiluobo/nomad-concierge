## 设计限制与交接检查

- 新字段在当前准备分支的旧 shared 中尚未完整定义；新增断言使用原始 HTTP/WS 与 QA 局部 wire 类型保留字段，不放宽原有共享协议验证。正式执行必须使用组装候选自己的 shared 并重新编译。
- SPEC 未固定 `pendingQuestions` 内问题文案的属性名，也未明确是否复用 UI 的动态“同本人国籍”/“不确定”选项。本次按同序问题内容、明确静态选项和 `allowUnsure` 核对，不强加 UI 选项生成方式；收到候选后再次核对该段文字及公开模型请求契约。
- E2E-026 只暂扣真实响应，不伪造计划或事件。必须观察到新计划事件之后的真实 UI 处理屏障；若该屏障不可见，或额外新快照可能掩盖旧快照覆盖问题，记受阻并改进测试控制，不据此报产品缺陷。
- E2E-027 不限定显示时区和 12/24 小时制；若时间展示格式不被解析器识别，附真实可见文本并转候选/人工复核，不能因格式差异报产品缺陷。
- E2E-028 的前置是真实计划含空阶段。SPEC 未保证特定诉求一定出现空阶段；若预设税务场景没有空阶段，记受阻并重新建立合法前置，不将缺少该前置当成产品缺陷，也不静默跳过或算通过。
- 旧摘要缺少三个可选统计字段、无效账号偏好存储两条兼容分支，列入 MAN-006 同候选开发前端测试证据移交；没有把它们计作已实现的真实后端 E2E 断言。
- MAN-001 的端口与重启场景是准备好的人工/操作检查，尚未运行。MAN-002～004 仍由负责人在人工验收时完成；MAN-005 及 ENV-005 仍等待最终交付包。
