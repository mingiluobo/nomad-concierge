## 复现

环境：macOS arm64、Node v24.22.1；独立候选副本执行 `npm ci`、`npm run build`，无 `.env`、无产品修改。每例独占进程、动态端口、全新 SQLite；`DEMO_DELAY_MS=1200`，模型 Key 和本地模型名为空，模型地址指向本地假服务。

1. 登录，保存 Cookie；连接同源 `/ws`，发送 `{"type":"resume","lastEventId":null}`，等待 `ready`。
2. `POST /api/conversations`，提交 `{"content":"我想搬到葡萄牙生活","clientMessageId":"<唯一值>","enginePreference":"rules"}`。
3. 轮询 `GET /api/conversations/:id`，确认 `activeTurn.status="running"`，记录任务 id 及 `attempt=1`。
4. 向本轮实际 API Node 进程发送 `SIGTERM`，等待退出；保存同一任务的 `queued` 事件及 WebSocket 关闭码。
5. 使用同一个 SQLite 文件启动新的 API 进程；等待原会话同一任务完成，再读取任务快照及消息接口。

首轮和新的独占实例复核均复现。单例复核命令为 `playwright test --project=api --grep 'API-074\b'`；应通过 QA harness 注入上述候选、临时数据库和进程配置。

## 预期与实际

原候选预期：该候选 SPEC §7.2 状态转移表明确规定 `running → queued` 的触发为“重启恢复、优雅停机（attempt + 1）”。§9.5 要求中止运行任务、条件更新回 queued 并写事件，再以 1012 关闭连接；未规定优雅停机免于递增。因此当轮依据该版本，要求从 attempt=1 退回 queued 后为 2，同库续跑完成后仍为 2。以下保留原候选的观察与判定依据。

实际（独占复核同一任务 `ab853499-96ae-44e6-9795-f0d50d5c326b`）：

| 时点 | 状态 | attempt | version |
| --- | --- | --- | --- |
| SIGTERM 前公开快照 | running | 1 | 2 |
| 停机公开事件 | queued | 1 | 3 |
| 同库新进程完成 | completed | 1 | 7 |

关闭码确为 1012；进程正常退出后启动了新进程；完成后消息共 2 条，其中助手 1 条。缺陷仅涉及恢复次数未递增，不将本次成功续跑表述为失败或数据丢失。
